# Positive control — full collapse-metric calibration (P0.2.2)

This Phase-0 sub-study (P0.2.2; see the [Phase 0 overview](index.md)) continues the collapse-instrument calibration of
[P0.2.0](P0.2.0.md) / [P0.2.1](P0.2.1.md) using the same vehicle (predictorless / stop-gradient-off SimSiam as the
forced-collapse arm vs. intact SimSiam as the genuine healthy baseline), and the same experimental envelope. P0.2.1
calibrated RankMe — and found its operating envelope (only the IID × 40-epoch corner certifies). P0.2.2 does the same
for the **rest of the collapse suite**, to find where each instrument responds and where it does not, and ultimately
whether the instruments complement each other by activating in different regimes without ever raising a false alarm on
the healthy arm.

## Why this exists (what P0.2.1 left open)

P0.2.1 proved RankMe separates a genuinely-collapsed representation from a genuinely-healthy one, and mapped where it
does so (IID × 40 epochs; it fails single-pass, and under correlation (the healthy arm is also suppressed). We need to
extend this to the remaining instruments in (`cafl4ds/measurements.py`) - for each we require a fire/quiet criterion.
Until that is done, a Phase-1 reading on any of them is uninterpretable, exactly as an un-calibrated RankMe was before
P0.2.1.

## Scope — the instrument set

The failure mode is unchanged (joint-embedding collapse, elicited by SimSiam's one-toggle ablation), so the relevant
suite is the joint-embedding geometry set. P0.2.2 calibrates the four that P0.2.1 did not:

| Instrument | `measurements.py` | VICReg/W&I term | Logged today? |
| -- | -- | -- | -- |
| Per-dimension variance | `feature_variance` | VICReg variance | yes (as `mean_feature_var`) |
| Off-diagonal covariance | `offdiag_covariance` | VICReg covariance | yes (as `offdiag_cov`) |
| Uniformity | `uniformity` | Wang & Isola uniformity | yes |
| Alignment | `alignment` | Wang & Isola alignment | **no** (needs positive pairs — see below) |

RankMe / effective rank is the reference (calibrated in P0.2.1), re-read here for direct comparison.

- **Prototype-assignment entropy is out of scope**: it is a `[prototype: DINO/SwAV]` metric, and the repo's collapse
    vehicle is joint-embedding SimSiam — calibrating it needs a prototype method + its own collapse ablation, which is a
    separate study.

- **Measurement surface: both layers.** VICReg's variance/covariance and Wang & Isola's alignment/uniformity are
    canonically defined on the **projector/expander output** `z`, where SimSiam's collapse fingerprint (the terminal
    `BatchNorm(affine=False)`) lives — but P0.2.1 read RankMe on the **backbone encoder output** (the
    downstream-relevant representation). P0.2.2 reads every metric at **both** surfaces, so the calibration also reveals
    *where in the network* each instrument is sensitive.

## Theory first — the instruments should *not* respond uniformly

SimSiam-collapse drives point collapse: every input maps to one constant vector (cosine → 1, loss → −1). The instruments
respond differently to that specific sub-mode, and the differences are predictable *before* any run — the calibration
confirms (or refutes) them:

| Instrument | Behaviour under point-collapse | Prediction |
| -- | -- | -- |
| **Per-dim variance** | → 0 (every dimension becomes constant) | **Fires cleanly** — likely the sharpest, most direct point-collapse readout. |
| **Uniformity** | → 0⁻ (embeddings clump; the potential climbs toward 0) | **Fires standalone** — clumping is a collapse signal on its own; it does *not* need to be read jointly with alignment (it is *alignment*, not uniformity, that is non-standalone — next row). |
| **Alignment** | → 0 (positives map to the same constant ⇒ "perfectly aligned") | **Looks healthy in isolation** — alignment *alone* is not a collapse detector (positives coincide under a healthy model too). Uniformity carries the standalone signal; alignment only qualifies *why* it moved. |
| **Off-diag covariance** | → 0 (all per-dim variance vanishes ⇒ covariance vanishes too) | **May never fire** — it targets *redundancy/dimensional* collapse (VICReg's mode), which point-collapse does not produce. A principled **null**. |

The off-diag-covariance null is a genuine calibration outcome, not a failure: it would show the instrument is calibrated
for a collapse *sub-mode* this vehicle does not exhibit.

## Methodology — the fire/quiet criterion

Each instrument gets a **two-sided** verdict, mirroring the P0.2.1 gate:

1. **Fires (true positive).** The PC (collapse) arm moves in the collapse direction (see the table above for each
    metric's sign) far enough to separate from the healthy arm — read as a **separation ratio** (`healthy / PC` or
    `PC / healthy`, oriented so >1 means separated) rather than an absolute floor, because P0.2.1 showed absolute
    thresholds do not transfer across scale/regime.
1. **Stays quiet (no false alarm).** The healthy arm does **not** move in the collapse direction — it holds a healthy
    value (or re-expands, as RankMe does in its U-shape).

**Normalization.** Variance and covariance are magnitude-dependent, so raw values are not comparable across
checkpoints/regimes. They are read on **L2-normalized** embeddings and via the separation ratio, never an absolute
threshold. Uniformity/alignment are already defined on the unit hypersphere.

**Robustness.** As in P0.2.1, the bar is the **minimum across seeds** (a casual re-run must pass on a bad draw), and the
crossover regions are run at ≥4 seeds.

## Experimental envelope

Base = the P0.2.1 envelope, reading **all** metrics at **both** surfaces. Staged so the map comes first and expansions
are driven by what it shows.

### Stage 1 — map each instrument's envelope

- **E1 — 2×2 regime matrix.** {IID, class-blocked} × {40 epochs, single pass}, seeds 0–3. The primary activation map:
    for each (metric × surface × corner), does it fire / stay quiet? Reuses P0.2.1's four corners exactly, so the
    readings are directly comparable to the RankMe calibration.
- **E2 — horizon sweep.** 5 → 80 epochs (IID, canonical config), min-across-seeds. Where does each metric *first*
    separate **robustly**, and does it plateau (as RankMe saturates by ~40 epochs)? Some instruments may certify at a
    **cheaper** horizon than RankMe — a useful result.

### Stage 2 — the correlation-strength axis + gap-filling

- **E3 — correlation-strength sweep.** The stream today has only the two extremes (`iid` = uncorrelated, `class_blocked`
    = maximally correlated). This axis adds **intermediate** orderings (a block-size / partial-shuffle mixing parameter
    on `EraStream`) and sweeps them, to trace which instruments are correlation-sensitive and at what correlation
    strength they activate. Directly probes the corner where RankMe fails **from above** (correlated × long horizon,
    healthy arm suppressed) — a candidate for complementarity.
- **E4 — LR sweep on single-pass (horizon vs. optimization).** Sweep the base LR on the single-pass IID cell to isolate
    the *optimizer* axis from the *data* axis that E2 confounds: does step size alone rescue the certified backbone gate
    at one pass? Also the concrete test of whether the single-pass detector (RankMe @ proj) survives across step sizes.

### Stage 3 — synthesize

Collect the per-instrument maps into a **coverage table** (which metric activates in which corner, at which surface).
Then decide — as a finding, not a premise — whether the suite is *complementary* (each instrument covering a regime the
others miss, no false alarms), and whether any persistent null (likely off-diag covariance) warrants a dedicated
redundancy-collapse positive control.

## Implementation additions (code)

The measurements exist; the wiring does not. Planned, all unit-tested:

1. **Projector-surface readout.** The monitor reads only `method.encode` (backbone). Add a method-agnostic surface
    accessor on `SSLMethod` (e.g. `embedding_surfaces(x) -> {"backbone", "projector"}`) and have the monitor compute
    each metric per surface. SimSiam already builds `z = projector(encoder.embed(x))` in `_branch`.
1. **Alignment wiring.** Alignment needs *positive pairs*; the monitor encodes a single view today. Add a two-view pass
    over the fixed probe-query set (via `method.two_view`) with a **fixed eval-time augmentation RNG** so pairs are
    comparable checkpoint-to-checkpoint. Guard behind a joint-embedding capability check (only pair-producing methods
    support it).
1. **Per-metric fire/quiet verdict.** Extend the gate/analysis (`scripts/positive_control.py` and its `gate` config, or
    a sibling analysis script) to emit, per (metric × surface × regime), the separation ratio and the two-sided verdict
    — with the L2-normalization for variance/covariance.
1. **Correlation-strength ordering.** Add an intermediate ordering mode to `EraStream` (block-size or partial-shuffle
    mix), with `iid` and `class_blocked` as its endpoints, plus config + unit tests.

## Contingency — a metric that never fires

If an instrument (most likely **off-diag covariance**) does not fire in **any** corner of Stage 1/2, the response is
**(a) accept and document, and (b) suggest the finding for a further (sub)-study** — *not* engineer a
redundancy-collapse control into SimSiam.

## How to run

```bash
# E1 — 2x2 matrix, all metrics at both surfaces (seeds 0-3):
for seed in 0 1 2 3; do
  uv run python scripts/positive_control.py seed=$seed                                   # IID x 40ep
  uv run python scripts/positive_control.py seed=$seed stream=class_blocked              # corr x 40ep
  uv run python scripts/positive_control.py seed=$seed epochs=1 eval_every_epochs=0.125  # IID x single pass
  uv run python scripts/positive_control.py seed=$seed stream=class_blocked epochs=1 eval_every_epochs=0.125
done

# E2 — horizon sweep (IID), reading all metrics (probes off => cheap):
for ep in 5 10 20 25 30 40 50 60 80; do for seed in 0 1 2 3; do
  uv run python scripts/positive_control.py epochs=$ep seed=$seed monitor.run_knn=false monitor.run_linear=false
done; done

# E3 — correlation-strength sweep: same-class run length via EraStream.block_size (a multiple of
# batch_size so eras never split a batch), IID and full class blocks as the endpoints, at 40 epochs:
for seed in 0 1 2 3; do
  uv run python scripts/positive_control.py epochs=40 seed=$seed stream=iid monitor.run_knn=false monitor.run_linear=false
  for bs in 128 256; do
    uv run python scripts/positive_control.py epochs=40 seed=$seed stream=class_blocked stream.block_size=$bs \
      monitor.run_knn=false monitor.run_linear=false
  done
  uv run python scripts/positive_control.py epochs=40 seed=$seed stream=class_blocked monitor.run_knn=false monitor.run_linear=false
done

# E4 — single-pass IID LR sweep (base LR 1e-3 x {0.25,0.5,1,2,4}), probes off, seeds 0-3:
for lr in 2.5e-4 5.0e-4 1.0e-3 2.0e-3 4.0e-3; do for seed in 0 1 2 3; do
  uv run python scripts/positive_control.py epochs=1 seed=$seed optim.lr=$lr \
    monitor.run_knn=false monitor.run_linear=false
done; done
```

The E2/E3 sweeps are long; run them on an available accelerator. E7/E8 are post-hoc:

```bash
uv run python outputs/_e7e8_analysis.py outputs   # E7 independence matrix + E8 seed-variance / bar-safety
```

## Findings

### E1 — the 2×2 activation map

Seeds 0–3 over P0.2.1's four corners ({IID, class-blocked} × {40 epochs, single pass}), every instrument read at both
surfaces. The bar is the robustness bar from P0.2.1 — the minimum separation across the four seeds (a casual re-run must
fire on a bad draw), against the provisional thresholds (ratio ≥ 2.0, gap ≥ 0.5). Variance/covariance are read on
L2-normalized embeddings.

**The certified RankMe gate reproduces P0.2.1 exactly** — it certifies only the IID × 40-epoch corner:

| Corner | Gate pass (seeds) |
| -- | -- |
| IID × 40 ep | **4 / 4** |
| corr × 40 ep | 0 / 4 |
| IID × single pass | 0 / 4 |
| corr × single pass | 0 / 4 |

**Robust firing map** (min-across-seeds separation; **FIRE** = clears its threshold in the collapse direction; a bare
number is quiet):

| Instrument | Surface | dir / scale | IID×40ep | corr×40ep | IID×1pass | corr×1pass |
| -- | -- | -- | -- | -- | -- | -- |
| **rankme** | backbone | down / ratio | **FIRE 2.46** | 1.45 | 1.20 | 1.14 |
| **rankme** | **proj** | down / ratio | **FIRE 6.85** | **FIRE 6.29** | **FIRE 2.11** | **FIRE 2.17** |
| mean_feature_var | backbone | down / ratio | 0.50 | 0.32 | 1.29 | 1.33 |
| **mean_feature_var** | **proj** | down / ratio | **FIRE 2.03** | **FIRE 2.30** | 1.04 | 1.01 |
| offdiag_cov | backbone | up / ratio | 0.02 | 0.94 | 0.17 | 0.26 |
| offdiag_cov | proj | up / ratio | 0.00 | 0.00 | 1.10 | 0.92 |
| uniformity | backbone | up / gap | 0.02 | −0.02 | 0.03 | 0.03 |
| **uniformity** | **proj** | up / gap | **FIRE 1.62** | **FIRE 1.45** | 0.23 | 0.28 |
| alignment | both | (paired) | — not a standalone detector (small gap; see below) — |  |  |  |

The table gives the **robust** (worst-of-four-seeds) separation. The per-seed spread at the projector is wide — e.g.
RankMe @ proj at IID×40ep is `[6.85, 18.47, 13.90, 24.48]` and variance @ proj is `[2.03, 9.04, 32.26, 28.68]` — so the
**magnitudes are seed-noisy at this toy scale** (they also shift with thread count / device); the **fire/quiet verdict
is the stable, reported result**, and the worst-seed margin is what the "FIRE" bar enforces.

What the map says:

1. **The surface is the dominant axis — collapse is legible at the projector, not the backbone.** Every robust fire
    except backbone-RankMe's happens at `proj`. That is exactly where SimSiam's collapse fingerprint lives (the
    terminal `BatchNorm(affine=False)`), so reading there is far more sensitive.
1. **RankMe @ proj is the universal detector — it fires in *all four* corners**, including the two single-pass corners
    and the correlated corner that P0.2.1 found dead for backbone RankMe. Reading RankMe at the projector rescues the
    corners the backbone cannot certify (single-pass still separates ~2.1×). This is the headline new result. **Caveat
    on the two single-pass corners:** P0.2.1 established that a single-pass *healthy* arm cannot be independently
    certified healthy (it is mid-transient / non-asymptotic at either surface), so the single-pass projector "fire" is
    a **relative** separation between two under-developed arms — *not* a fire against a certified-quiet baseline the
    way the IID×40ep corner is. It is a genuine detector to carry into Phase-1, but with that asterisk, not a full
    two-sided pass.
1. **RankMe @ proj is also the most *reliable* detector** — its worst-seed margin stays large in every corner (min 6.85×
    at IID×40ep, still 2.1× at single pass), so the fire is never marginal.
1. **RankMe @ backbone reproduces P0.2.1** — it fires only in IID × 40 ep (2.46×), the same one corner, a clean
    cross-check that the P0.2.2 wiring did not move the reference.
1. **Variance @ proj and uniformity @ proj are long-horizon detectors** — both fire robustly in **both** 40-epoch
    corners and stay quiet single-pass; at the backbone neither ever robustly separates. Note a theory caveat: variance
    is the *sharpest* readout on a typical seed (up to ~30× at IID×40ep), matching the prediction, but it is also the
    *noisiest* — its worst seed drags the robust margin down to 2.03×, right at the bar.
    **`mean_feature_var @ backbone` is worse than merely quiet — it is *sign-unstable* across seeds:** at IID×40ep the
    collapse arm's backbone variance is 15× *lower* than healthy on seed 0 but ~2× *higher* on seed 3 (the 0.50 robust
    "separation" in the table is that seed-3 sign flip, not a small margin). So the backbone variance reading is not
    even directionally consistent about *which* arm collapsed — a sharper justification for "read at the projector"
    than "it stays quiet."
1. **Off-diagonal covariance is a confirmed null — it never fires robustly, at either surface, in any corner.** This is
    precisely the theory-table prediction: point-collapse drives *all* per-dimension variance → 0, so the covariance
    vanishes too; the instrument targets *redundancy/dimensional* collapse, which the SimSiam vehicle does not produce.
    *(Later narrowed by [P0.2.4](P0.2.4.md): `offdiag_cov @ backbone` does false-fire on an undertrained-but-healthy
    representation, so the null holds cleanly **at the projector**, not literally either surface.)*
1. **Alignment stays small and healthy-looking under collapse**, as predicted — positives map to the same constant, so
    it reads "perfectly aligned". Confirmed *not* a standalone detector. Note this concerns *alignment*, not
    uniformity: `uniformity @ proj` fires standalone above and needs no joint align–uniformity gate — alignment only
    qualifies the interpretation of a uniformity move.

### E2 — horizon sweep

Sweeps training budget (epochs 5, 10, 20, 25, 30, 40, 50, 60, 80) at IID, probes off, seeds 0–3, to find the *cheapest
horizon at which each instrument first fires robustly* and whether anything certifies sooner than the backbone RankMe
gate. Robust map (MIN separation across seeds; ratio ≥ 2.0, gap ≥ 0.5):

| instrument | ep5 | ep10 | ep20 | ep25 | ep30 | ep40 | ep50 | ep60 | ep80 |
| -- | -- | -- | -- | -- | -- | -- | -- | -- | -- |
| RankMe @ backbone | 0.94 | 1.18 | 1.82 | **FIRE** 2.07 | **FIRE** 2.18 | **FIRE** 2.55 | **FIRE** 2.82 | **FIRE** 2.63 | **FIRE** 2.81 |
| RankMe @ proj | **FIRE** 3.81 | **FIRE** 6.79 | **FIRE** 13.1 | **FIRE** 12.8 | **FIRE** 15.2 | **FIRE** 12.2 | **FIRE** 12.9 | **FIRE** 10.7 | **FIRE** 18.5 |
| mean_feature_var @ proj | 1.31 | **FIRE** 2.54 | **FIRE** 3.42 | **FIRE** 7.00 | **FIRE** 8.99 | **FIRE** 13.9 | **FIRE** 4.89 | **FIRE** 3.16 | **FIRE** 6.36 |
| uniformity @ proj | **FIRE** 0.84 | **FIRE** 1.40 | **FIRE** 2.00 | **FIRE** 2.21 | **FIRE** 2.16 | **FIRE** 2.23 | **FIRE** 2.07 | **FIRE** 2.09 | **FIRE** 2.45 |
| offdiag_cov (both) | null | null | (2.50)† | null | null | null | null | null | null |
| certified RankMe gate | 0/4 | 0/4 | 1/4 | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 |

Backbone `mean_feature_var`/`uniformity` are null across the whole sweep; alignment is paired-only (omitted). †The lone
`offdiag_cov @ backbone` FIRE at ep20 is spurious — it is isolated and non-monotonic (near-bar 1.94 at ep5, 2.50 at
ep20, then collapses to ~1 and to 0 at long horizons), i.e. a worst-seed artifact, not a detection.

Findings:

1. **The certified (backbone) gate is horizon-expensive: it needs ≈ 25 epochs to fire robustly.** It is 0/4 through
    ep10, only 1/4 at ep20, and first hits 4/4 at ep25 — after which it holds. Below ~25 epochs the certified gate
    simply misses point-collapse. Read together with E3 (where the same gate is IID-only), the backbone RankMe gate is
    doubly constrained: it needs both a *long horizon* and an *IID stream* to work.

1. **The projector-surface detectors fire almost immediately.** RankMe @ proj and uniformity @ proj both FIRE at the
    very first checkpoint (ep5) and stay lit at every horizon; `mean_feature_var @ proj` needs only ~10 epochs. So
    collapse is legible at the projector after a fraction of the training the backbone gate requires — roughly a 5×
    cheaper detection horizon (ep5 vs ep25).

1. **Detection order by cost is stable:** uniformity @ proj ≈ RankMe @ proj (ep5) < variance @ proj (ep10) ≪ RankMe @
    backbone / certified gate (ep25) ≪ off-diag covariance (never). This is a clean cost ranking of the suite along the
    training-budget axis and is monotone once each instrument switches on (no instrument un-fires at longer horizons).

1. **Off-diag covariance never fires** (the ep20 blip aside), consistent with E1/E3 and theory.

1. **RankMe's reading is monotone in collapse *depth*, not only a healthy-signal plateau.** The widening separation is
    two-sided: as the forcing horizon grows the healthy arm's RankMe *saturates* while the PC arm's *own* RankMe@bb
    keeps *sinking* — `2.69 → 2.48 → 2.22 → 2.07 → 1.99 → 1.93 → 1.92 → 1.77 → 1.67` over ep5→80 (mean across seeds), a
    monotone deepening of the collapse limb. So on the *deep-collapse* side the instrument scales monotonically with
    severity — real (if partial) evidence RankMe reads collapse *depth*, and a down-payment on the incipient-collapse
    dose-response flagged as the mode's defining open gap ([P0.2 audit](../audits/P0.2.md), C1). It does **not** close
    C1: the untested continuum is the *healthy-to-incipient* side, which this deep-forcing sweep never populates.

**Takeaway:** the horizon axis tells the same story as the correlation axis (E3) from a second direction. The
projector-surface instruments are not just the *robust* core but also the *early* core — they see collapse within a few
epochs, whereas the certified backbone gate only becomes reliable after a substantial training budget. For Phase-1's
short-horizon, non-IID streaming regime, a monitor built on the backbone gate alone would be both too slow and too
fragile; the projector-surface pair is the right foundation.

### E3 — correlation-strength sweep

Sweeps the same-class run length (`EraStream.block_size`: IID → 128 → 256 → full ~400-image class blocks) at 40 epochs,
probes off, seeds 0–3. This traces which instruments are *correlation-sensitive* and pins down where the certified
backbone-RankMe gate's failure sets in. Robust map (MIN separation across seeds; thresholds ratio ≥ 2.0, gap ≥ 0.5):

| instrument | IID | bs128 | bs256 | class_blocked |
| -- | -- | -- | -- | -- |
| RankMe @ backbone | **FIRE** 2.23 | 1.46 | 1.21 | 1.24 |
| RankMe @ proj | **FIRE** 11.28 | **FIRE** 6.14 | **FIRE** 7.26 | **FIRE** 8.34 |
| mean_feature_var @ proj | **FIRE** 13.91 | **FIRE** 2.70 | 1.81 | **FIRE** 2.65 |
| offdiag_cov (both) | null | null | null | null |
| uniformity @ proj | **FIRE** 2.36 | **FIRE** 1.38 | **FIRE** 1.44 | **FIRE** 1.59 |
| certified RankMe gate | 4/4 | 0/4 | 0/4 | 0/4 |

(Backbone-surface `mean_feature_var`/`uniformity` and `offdiag_cov @ proj` are null across the whole sweep, as in E1;
alignment is paired-only. Omitted for brevity.)

> **Seed-count note.** The min-across-seed values above are from 4 seeds and drift with seed count. A 16-seed rerun (the
> D1 audit rider; [`artifacts/P0.2.2/E3_16seed/summary.json`](artifacts/P0.2.2/E3_16seed/summary.json)) supersedes the
> valley / bs256 reading below — see findings 2–3.

Findings:

1. **Correlation strength is exactly what defeats the certified (backbone) gate.** The P0.2.1 gate and RankMe @ backbone
    fire cleanly at IID (2.23×, 4/4) and go quiet the moment any same-class blocking is introduced (0/4 at every block
    size). The failure is not gradual — even the mildest correlation (bs128) already drops the margin below the bar.
    This is the "from-above" blind spot the sweep was designed to locate, and it sets in immediately.

1. **The projector detectors fire at *every* correlation level, and correlation robustly weakens them — but it is not a
    "valley," and not "invariant."** RankMe @ proj and uniformity @ proj clear the bar at every correlation strength,
    so point collapse in projector geometry stays legible regardless of stream ordering. The 4-seed sweep above
    *looked* like a **mild-correlation valley** — RankMe @ proj dipping to a minimum at bs128 and recovering at full
    blocks — but a 16-seed rerun (the D1 audit rider) does **not** replicate that shape. Across 16 seeds RankMe @ proj
    separation is markedly higher at IID (mean 17.4, median 15.3) than at *any* correlated block size (means 7–9), and
    the differences *among* the correlated cells sit within seed noise — the worst min is at full class-blocking
    (3.73), not at the intermediate bs128. So the robust picture is a **~2× haircut the moment correlation appears,
    then roughly flat**: no reliable intermediate dip and no full-block recovery. Two results survive and matter for
    Phase-1 (real streams are *partially* correlated): RankMe @ proj **never fails the 2.0 bar** at any correlation
    across all 16 seeds (P(< bar) = 0), so it stays the robust core detector; `mean_feature_var @ proj`, by contrast,
    dips below the bar seed-dependently under correlation (≈ 6–12 % of seeds at bs128 / full blocks), confirming it
    must never be a standalone gate.

1. **`mean_feature_var @ proj` is the noisy exception again.** Its robust margin sits right on the threshold, so a
    single bad draw pushes it under. The 4-seed sweep put that dip at bs256 (1.81×), but the 16-seed rerun shows the
    below-bar draws are seed-dependent and land at bs128 (min 1.86) and full class blocks (min 1.73), *not* at any
    fixed correlation level (bs256's 16-seed min is 2.47, above the bar). So the dip is a worst-seed effect, not a
    trend — re-confirming E1's verdict that variance @ proj is sharpest-on-a-typical-seed but least reliable, and never
    a standalone gate.

1. **Off-diag covariance stays null across the entire correlation axis**, closing off the hypothesis that correlated
    eras might induce enough redundancy to trip it under point-collapse. Consistent with E1 and theory; the
    redundancy-collapse follow-up ([P0.2.3](P0.2.3.md), Barlow/VICReg vehicle) remains the right home for that
    instrument.

**Takeaway:** the projector-surface pair (RankMe, uniformity) is the correlation-robust core of the suite. The certified
backbone gate is an *IID-only* instrument, and E3 shows its failure boundary is sharp and early — motivating the
surface-aware, multivariate monitor rather than a single backbone-RankMe gate for Phase-1's non-IID streams.

### E4 — single-pass LR sweep (horizon vs. optimization)

E2 showed the certified backbone gate needs ≈ 25 epochs, but *epochs* confounds two things — **more optimizer steps**
and **more data seen**. E4 isolates the optimizer: a fixed **single pass** over the IID stream (data held constant),
base LR (`1e-3`) × {0.25, 0.5, 1, 2, 4}, seeds 0–3, probes off. The question is whether step size *alone* rescues the
certified backbone gate at one pass — i.e. whether E2's horizon cost decomposes into steps × step-size. Robust map (MIN
separation across seeds; thresholds ratio ≥ 2.0, gap ≥ 0.5):

| instrument | 0.25× | 0.5× | 1× (base) | 2× | 4× |
| -- | -- | -- | -- | -- | -- |
| RankMe @ backbone | 1.07 | 1.07 | 1.17 | 1.07 | 1.07 |
| RankMe @ proj | 1.71 | 1.96 | **FIRE** 2.14 | **FIRE** 2.00 | **FIRE** 2.01 |
| certified RankMe gate | 0/4 | 0/4 | 0/4 | 0/4 | 0/4 |

(`mean_feature_var @ proj`, `uniformity @ proj` and `offdiag_cov` are null across the whole LR sweep — single pass is
below their detection horizon regardless of step size, consistent with E2; omitted for brevity.)

Findings:

1. **Step size does not rescue the certified backbone gate at single pass — 0/4 at every LR.** RankMe @ backbone is flat
    at ~1.1 with no LR trend. So E2's ≈ 25-epoch requirement is a genuine cost.
1. **RankMe @ proj — the single-pass detector from E1 — fires only at base LR and above** (2.0–2.14×) and dips *below*
    the bar at 0.25×/0.5× (1.71/1.96). At sub-base LR the healthy arm is undertrained, so its projector geometry has
    not expanded and the PC/healthy separation shrinks. The single-pass rescue is real but conditional on an
    adequately-warm optimizer.
1. **The long-horizon detectors stay null across the entire LR sweep**, re-confirming they are horizon-bound, not
    step-size-bound.

**Takeaway:** E4 pins the certified backbone gate's cost to *data-passes*, not step size — it cannot be recovered by
tuning the optimizer in a single-pass stream, which matters directly for Phase-1's single-pass streaming regime. The
projector-surface RankMe remains the only single-pass detector, with the added caveat that it needs at least the base LR
to fire.

### E7 — instrument-independence matrix (post-hoc, no new runs)

Substantiates the qualitative "complementary, no strict proxy" claim with a number. Pool the `separation` reading of
**every** E1–E4 run (88 runs) and compute the **Spearman rank-correlation** of each standalone instrument×surface pair
across the pool (`outputs/_e7e8_analysis.py`). Rank-based because the per-seed magnitudes are noisy and the ratio/gap
scales differ; a *strict proxy* would show |ρ| → 1.

| ρ (Spearman) | rankme@bb | rankme@proj | var@proj | unif@proj |
| -- | -- | -- | -- | -- |
| **rankme @ backbone** | 1.00 | 0.82 | 0.78 | 0.82 |
| **rankme @ proj** | 0.82 | 1.00 | 0.85 | 0.92 |
| **mean_feature_var @ proj** | 0.78 | 0.85 | 1.00 | 0.93 |
| **uniformity @ proj** | 0.82 | 0.92 | 0.93 | 1.00 |

Findings:

1. **No pair is a strict proxy.** The strongest coupling among the fire-capable detectors is ρ ≈ 0.92–0.93 (the
    projector trio), well short of 1.0 — so E1's four distinct firing patterns are *not* one underlying signal read
    four ways.
1. **But the complementarity lives in firing-*coverage*, not magnitude independence.** The projector trio (RankMe /
    variance / uniformity @ proj) is *strongly* rank-correlated (0.85–0.93): as raw magnitudes they carry substantially
    overlapping information — unsurprising, they all read point-collapse at the same surface. What makes them
    complementary is **where each crosses its fire bar** (the E1–E4 envelope: RankMe @ proj universal, variance /
    uniformity @ proj long-horizon-only), not statistically independent readings. This *refines* the earlier claim:
    independent **coverage**, correlated **magnitude**.
1. **The backbone gate is the most distinct useful detector** (ρ 0.78–0.82 to the projector trio, the lowest couplings
    in the table) — it carries the most independent information, consistent with it being the one downstream-relevant
    surface, and reinforces keeping it as a reference alongside the projector pair.
1. **`offdiag_cov @ proj` shows ρ = −0.99 vs `var @ proj`** — a *mechanical* anti-correlation (both are functions of the
    same normalized covariance matrix; under point-collapse variance → 0 drags both), not an independent detection
    signal, since off-diag never fires (E1–E3). Flagged so the near-perfect number is not mistaken for a finding.

### E8 — estimator variance / bar safety (post-hoc, seed replicates)

The *cheap* post-hoc variance estimator is the **4-seed replicate spread already on disk**. Per cell
(`outputs/_e7e8_analysis.py`): coefficient of variation (CoV = std/mean), the `min` (the robustness statistic the bar
uses), the single-draw miss rate P(seed < bar), and the bootstrapped P(min-of-4 < bar). This turns E1/E3's "variance @
proj is marginal" caveat into a number and asks, of each reported FIRE, whether it is **safe** or **noise-limited**.

Findings:

1. **Every reported robust FIRE is safe — with exactly one exception.** In all cells where E1–E4 report a robust FIRE,
    the bootstrapped P(min-of-4 < bar) = **0.00** with a wide margin, *except* **`mean_feature_var @ proj` at
    E3/bs256**, where P(min < bar) = **0.68** (25 % single-draw miss). This confirms and quantifies the pre-existing
    caveat: the bs256 dip is a genuine noise-limited straddle, so variance @ proj **must never be a standalone gate**.
1. **`mean_feature_var @ proj` is by far the noisiest instrument** — CoV **0.8–1.7** in its firing cells (up to ~120×
    *mean* separation at E2/ep50), versus 0.07–0.5 for RankMe @ proj. Its typical-seed sharpness comes with enormous
    seed variance; the worst-of-seeds bar is exactly what keeps it honest.
1. **RankMe @ proj and the certified backbone gate are safe in their certified regimes.** RankMe @ proj has CoV ≤ 0.5
    and P(min < bar) = 0 everywhere it robustly fires (its only straddle is E4/lr0.5×, the sub-base-LR "from below"
    corner E4 already documents). RankMe @ backbone straddles *only* at the E2/E3 certification-**boundary** cells
    (ep20, bs128/bs256) and is clean (P = 0) throughout the certified IID × ≥25-epoch interior — so the P0.2.1 gate
    sits safely *inside* its boundary, not on it.
1. **`uniformity @ proj` is safe in its firing cells** (40-epoch / E2 ep10+ / E3, all P(min < bar) = 0); its straddles
    are confined to the single-pass and E4 corners where it is *not* claimed to fire.

**Caveat.** This uses the *seed axis* as the resampling population (4 draws/cell) — the only variance estimator
available without new runs. A genuine per-sample / eval-set-size bootstrap (needs stored embeddings or a
`stream.era_eval_per_class` sweep) remains a cheap Phase-1 follow-up if a sharper CI on a single cell is ever needed,
but the seed spread already resolves the one marginal instrument decisively.

**Takeaway (E7 + E8):** E7 shows the suite's complementarity is real but lives in *firing-regime coverage*, not
magnitude independence (the projector trio is strongly rank-correlated); E8 shows every reported FIRE is statistically
safe except `mean_feature_var @ proj` at bs256, ratifying its "never a standalone gate" status. Neither changes the
operating conclusions of E1–E4.

## Insights

- **The suite is complementary — no instrument is a strict proxy — but the complementarity is in *coverage*, not
    magnitude.** E1 yields four distinct robust firing patterns across the standalone instrument×surface pairs: *all
    four corners* (RankMe @ proj), *IID×40ep only* (RankMe @ backbone), *both 40-epoch corners* (variance @ proj and
    uniformity @ proj), and *never* (off-diag covariance) — so **(a)** every standalone instrument except off-diag
    covariance fires under *some* regime, and **(b)** they cover different regimes. E7 sharpens this: the projector trio
    is *strongly* rank-correlated in magnitude (ρ ≈ 0.85–0.93) yet no pair reaches a strict-proxy ρ → 1, so the
    operationally-useful complementarity is **where each crosses its fire bar** (the E1–E4 regime envelope), not
    statistically independent readings. Sharpened operationally, the point-collapse set reduces to a small core:
    **RankMe @ proj** (universal), **variance @ proj** (the point-vs-redundancy discriminator, kept *despite* its
    noise), and **offdiag_cov @ proj** (the redundancy-sub-mode detector, calibrated on its fire side in
    [P0.2.3](P0.2.3.md)). `uniformity @ proj` is near-redundant with RankMe @ proj (ρ ≈ 0.92, no corner of extra
    coverage) and the entire backbone surface is a *reference*, not a detector — so neither is load-bearing in the
    operational set.
- **The measurement surface is a first-class calibration axis, not a detail.** The single biggest lever on sensitivity
    is *where* the instrument reads: backbone vs. projector changes RankMe from a one-corner detector into a four-corner
    one. Phase-1 health monitoring should read the geometry instruments at the projector surface, and keep the backbone
    reading only as the downstream-relevant reference.
- **Off-diag covariance is honestly out-of-envelope here.** Its null is a *correct* calibration outcome that keeps the
    metric↔method mapping honest (it is a decorrelation-method instrument), and it defines a concrete follow-up rather
    than a gap.

### Explicit Phase-1 carry-overs (NOT closed here)

- **Threshold/scale transfer.** Every threshold (the certified gate + the 2.0 / 0.5 fire bars) is tuned at *toy* scale
    (tiny ViT, 32px, `proj_dim` 256). Whether the separations survive a real backbone / different embedding dim is a
    genuine risk, but it is a Phase-1 scaling question, not collapse calibration. Flagged so it is not silently assumed.
- **Drift under collapse (`cka_drift`/`cosine_drift`).** These are the forgetting/instability instruments (P0.3/P0.4),
    but they ride in the same health series and *should* spike under point collapse — a quick confirmation would be a
    free bridge to the next sub-studies. Belongs to P0.3, not here.
